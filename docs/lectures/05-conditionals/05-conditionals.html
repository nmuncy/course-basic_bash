Exit Status

  • Every command returns an exit status
  • Held on special variable $?
  • 0: command was successful
  • >0: command was unsuccessful
    • Each number has specific meaning
echo hi
echo $?
asdf
echo $?
hi
0
bash: line 2: asdf: command not found
127

Use Exit Status

  • Special commands && and || evaluate $?
  • && listens for exit status 0
    • if 0 (success) then process continues
  • || listens for exit status >0
    • if >0 (fail) the process continues
  • Can be combined
  • Keep these simple!
echo hi && echo pass || echo fail
asdf && echo pass || echo fail
hi
pass
bash: line 1: asdf: command not found
fail

Square Braces

  • Square braces ‘[]’ evaluate an internal statement to set exit status
  • Internal exit status 0: external exit status 0
  • Internal exit status >0: external exit status 1
  • White space (spaces) is very important!
[ 1 == 1 ] && echo true || echo false
[ 1 == 2 ] && echo true || echo false
[ a == a ] && echo pass $? || echo fail $?
[ a == b ] && echo pass $? || echo fail $?
true
false
pass 0
fail 1

Conditionals: if

  • Conditional syntax utilize square braces for workflow control
    • i.e. execute commands only if a condition is met
  • Syntax structure:
    • if [ assertion ]
    • New line then
    • Commands
    • New line fi to close conditional
  • Conditional work only executed if exit status = 0
if [ 1 == 1 ]; then
    echo Yay
fi
if [ 1 == 2 ]; then
    echo Nay
fi
Yay
  • Why is == used and not =?

Conditionals: elif

  • Ability to capture workflow if first conditional fails
  • elif (else if) assessed only when if exit status = 1
  • An entire new conditional is written
  • Read conditionals top -> bottom
  • Multiple elif statements allowed
foo=bat
if [ $foo == bar ]; then
    echo foobar
elif [ $foo == baz ]; then
    echo foobaz
elif [ $foo == bat ]; then
    echo foobat
fi
foobat
  • How many conditionals failed?
  • What if foo=baz?

Conditionals: else

  • else catches all failed conditions
  • Specified last
  • Does not evaluate an assertion
foo=foo
if [ $foo == bar ]; then
    echo foobar
elif [ $foo == baz ]; then
    echo foobaz
elif [ $foo == bat ]; then
    echo foobat
else
    echo "Unrecognized value of foo"
fi
Unrecognized value of foo

Conditionals: and

  • Multiple assertions can be combined with &&
  • As before, && only continues if exit status = 0
    • So, all conditionals would need to be true
foo=bar
num=1
if [ $foo == bar ] && [ $num == 1 ]; then
    echo Success
fi
Success
  • Would [ $num == 1 ] be assessed if foo=baz?

Conditionals: or

  • Assertions can also be combined with ||
  • As before, || only continues if exit status >0
    • So, only one of the assertions needs to be true
  • These can be combined with &&
alpha=a
num=1
if [ $alpha == b ] || [ $num == 1 ]; then
    echo Success
fi
Success
  • If the assertion was written [ $alpha == a ], would [ $num == 1 ] have been assessed?
  • Which of the assertions triggers the conditional in:
[ 1 == 2 ] && [ a == a ] || [ b == b ]

Conditionals: not

  • The character ! inverts logic
  • [ 1 != 0 ]: true ($?=0)
  • [ ! 1 == 0 ]: true ($?=0)
  • Note the white space in the second assertion
  • Useful to name variables to help reader through logic
[ a != b ] && echo $?
[ ! foo == bar ] && echo $?
0
0
  • What is printed in:
[ ! foo == bar ] && echo alpha \
    || echo beta
[ foo == bar ] || [ ! 1 == 2 ] \
    && echo delta || echo gamma

Comparing integers

  • A set of special comparators operators for integers
    • -gt: greater than
    • -lt: less than
    • -ge: greater than or equal
    • -le: less than or equal
    • -eq: equal
    • -ne: not equal
  • Note: double parentheses are used for mathematic expressions (>, <, <=, etc)
    • (( 1 <= 2 ))
  • See more details here
[ 1 -lt 2 ] && echo 1 $?
[ ! 1 -gt 2 ] && echo 2 $?
[ 1 -le 2 ] && echo 3 $?
[ ! 1 -ge 2 ] && echo 4 $?
1 0
2 0
3 0
4 0
  • What is printed in:
[ ! 1 -lt 2 ] && [ 1 -eq 1 ] \
    && echo alpha || echo beta
[ 1 -gt 2 ] || [ ! 1 -ge 2 ] \
    && echo delta || echo gamma

File management

  • A set of special comparators operators for managing files
    • -e: something exists
    • -d: a directory exists
    • -f: a file exists
    • -s: a file contains data
    • -z: a variable is empty
[ -f foo.txt ]
[ -e foobar ]
[ -d my_dir ]
[ -z $foo ]
  • What is printed in:
echo "foo" > my_file.txt
[ ! -s my_file.txt ] \
    && echo alpha || echo beta

Best practices

  • Keep conditionals below 3 levels of logic:
    • Simple, flat, short
  • Consider breaking up long chains into multiple statements
  • Inverting logic often simplifies
  • Name variables to help through logic
    • is_empty: holds boolean of whether file is empty
    • file_exists: holds boolean of whether file exists
# Flight control with variable
foo=""
foo_empty=$([ -z $foo ] && echo $? || echo $?)
[ $foo_empty == 0 ] && echo set_var || echo move_on

# Flight control with file
touch foo.txt
foo_exists=$([ -f foo.txt ] && echo $? || echo $?)
[ $foo_exists == 0 ] && echo move_on || echo make_foo
